# 智能体技能开发指南

**版本**：v2.0（2026-10-08，替代 9 月版《开发规范》与《开发操作指南》）
**发布**：Platform Platform Admin
**适用对象**：各部门智能体开发与知识库维护人员
**配套**：《知识库使用说明》；公司《关于智能体开发验收的通知》（2026-09-29）

**平台 2.1.0 打包补充**：新版清单、包内组件与上传检查见[《智能体打包与上传说明》](智能体打包与上传说明.md)。本文保留原业务开发规范。

## 一、概念与目标（与公司验收通知的对应）

公司通知界定：**智能体（Agent）= 以部门核心业务逻辑为核心、配置专属知识库、通过大模型调度多个技能、自动完成特定业务任务的 AI 应用系统**。每部门至少 **2 个智能体**（2026-10-15 集中验收）。

技术落地形态——两类技能（Skill）：

| 概念 | 定义 | 数量 | 对应通知特征 |
|------|------|------|------------|
| **主编排技能 = 智能体** | 一条核心业务的全流程入口：承载业务 SOP，分派功能技能并收口产物 | 每部门 2 个 | ①业务逻辑为核心 ③调度多技能 ④可交付他人使用 |
| **功能技能** | 被分派的能力单元，完成一个章节/子任务/通用工具职能 | 按需 N 个 | ②知识库配置由其声明并调用 |

通知四特征即验收标准：开发时逐条对照——**缺知识库依赖、只调一个技能、不可交付他人使用，均不合格**。

## 二、命名规范

| 项 | 规则 | 示例 |
|----|------|------|
| 智能体显示名 | `{业务名}智能体` | 可研报告编制智能体 |

| 功能技能（业务型） | `{专业门类}-{具体环节}` / ID：`{部门代码}-{环节}` | 市场分析-需求规模测算 / zxs-market-demand |

**红线**：**显示名一律使用中文**（直观可读，业务人员一看即懂），≤20 字，分隔符统一用英文连字符 `-`（不用全角破折号）；**功能技能显示名禁用"智能体/专家/调度"字样**（防止滥贴标签，"智能体"仅用于主编排）；系统 ID 全小写英文/拼音（机器标识，员工无需记忆），禁中文空格下划线；专业门类不得同名不同义。

## 三、SKILL.md 内容标准

每个技能一个 SKILL.md。**文件头（frontmatter）**：name / display_name / type（agent=智能体、functional=功能）/ subtype（business 或 tool）/ version / owner_dept / description。

**description 是被 Agent 自动调用的唯一依据**，必须含三要素、≤150 字：①干什么（一句职责）；②何时触发（什么任务表述应命中）；③输入什么、输出什么。反例："一个强大的分析工具"——永远不会被正确触发。

**正文七段**（按序，智能体另加粗体四件）：

| # | 段落 | 要点 |
|---|------|------|
| 1 | 功能描述 | 一句职责 + 边界（内/外各 2-3 条） |
| 2 | 输入契约 | 必需输入（缺一不可启动）、可选输入、格式 |
| 3 | 输出契约 | 交付物清单、格式（正式产物须 DOCX/XLSX/PPTX）、命名、质量标准 |
| 4 | 工作流 | 编号步骤：做什么 / 用什么（功能技能、知识库）/ 产出什么。**智能体用"业务 SOP 阶段表"承载** |
| 5 | 闸口 | 见下表，至少声明启动/交付/失败三类 |
| 6 | 知识库依赖 | 用到必填，格式见第五节 |
| 7 | 约束红线 | 数据口径、来源标注、禁止事项 |

**智能体四件套**（正文必须额外包含）：**①SOP 阶段表**（阶段/工作内容/依赖技能/产物）；**②任务→功能技能映射表**（任务/章节、分派技能、输入、输出，一行一任务）；**③分派规则**（易混淆意图写可执行判定条件，如"消息含'修订'且提供了已有报告→修订分支，否则新编分支"，禁止"灵活判断"式描述）；**④产物收口**（汇总各章节→查口径/编号/数据一致性→组装终稿→过交付闸。**只转发分派结果不收口=不合格**）。

**五类标准闸口**（不得自造概念）：

| 闸口 | 时机 | 动作 |
|------|------|------|
| 启动闸 | 任务开始前 | 确认目标、口径、材料清单，缺项先补齐 |
| 数据闸 | 使用关键假设/外部数据前 | 请用户确认；无法确认标"估算/待核验" |
| 阶段闸 | 大纲/阶段产物完成后 | 用户确认后再展开 |
| 交付闸 | 终稿完成时 | 逐项过自检清单后交付 |
| 失败闸 | 工具失败/知识库未命中/下游报错 | 立即停止该步，如实报告，禁止绕过拼凑 |

**质量红线**（通用）：禁硬编码密钥口令；禁依赖个人电脑绝对路径；引用数据必标来源；一个功能技能只做一件事（发现"顺便"做了第二件事→拆分或交智能体分派）。

## 四、知识库依赖声明（功能技能的灵魂）

智能体与功能技能凡用到库，在第六段按下表声明（**dept 写死本部门**，保证检索范围稳定；查询意图用自然语言——检索系统支持语义匹配，不只匹配字面）：

```markdown
## 6. 知识库依赖
| 工作流步骤 | dept | 目录 | 查询意图（自然语言） | 未命中处理 |
|-----------|------|------|---------------------|-----------|
| 市场测算 | 咨询所 | 05-数据资料库/{行业} | "{行业}近年市场规模与增速" | 换词重试→公开数据标"估算"→交付闸提示 |
```

**未命中处理三选一**：换检索词重试 / 降级方案（标注估算/待核验）/ 停下询问用户。**禁止静默跳过或编造来源**。

## 五、从零开始：手把手操作指引

> 本章面向第一次接触的开发人员。按顺序做，每步完成打勾。

### 第 0 步：配置 MCP 连接器（一切工作的前提，一次性，勿跳过）

登录 SkillHarbor 门户（http://127.0.0.1:8900）→ 首页点「**AI 使用指引**」→ **下载一键配置脚本（.bat）→ 双击运行一次**。脚本自动完成：WorkBuddy（及本机 Trae）的能力网关连接配置、技能安装与自动同步注册——**无需任何手动添加**。

- 浏览器提示安全警告时选「仍要运行」；已打开 WorkBuddy 的重启后生效；
- 连接成功的标志：WorkBuddy 工具列表出现 `list_skills`、`kb_search` 等工具；
- 连不上先重跑一次脚本；仍不行联系Platform（新机器需登记 IP→姓名映射）。

### 第 1 步：拿到本部门知识库写权限

用 SkillHarbor 账号登录门户（http://127.0.0.1:8900）→ 工作台 → 知识库：能看到全部库（只读）即通道正常。**本部门库出现"上传文件"按钮 = 你已有写权限**；没有的话由部门负责人向Platform申请加入白名单。

### 第 2 步：把业务素材入库（P0 三类）

以咨询所"可研报告"业务线为例：

1. 收集材料：现行可研模板 docx、编制说明、近两年可研成果 2-3 份（脱敏）；
2. 逐份按命名公式改名：`M-可研报告模板-产业园区-2026-v2.docx`（类别码 M/F/C/P/D/S/T）；
3. 门户知识库 → 本部门库 → 进入对应目录（01-模板库等）→「上传文件」多选上传；
4. 验证：搜索框输入一句自然话（如"可研模板"）能搜到刚传的文件即入库成功。

### 第 3 步：用 WorkBuddy 的【skill开发】技能生成 SKILL.md（不手写）

1. 在 WorkBuddy 对话中召唤「**skill开发**」技能，把以下信息一次性给它：部门与业务线、业务流程阶段（SOP）、各章节/任务想分派的功能技能、输入输出物、要查知识库哪些目录；
2. AI 按规范自动生成 SKILL.md 草稿（frontmatter + 七段结构，智能体含四件套）；
3. **人工逐段核对**（质量责任仍在开发者）：description 三要素是否准确、任务映射表是否与实际流程一致、闸口是否可执行、约束红线是否完整；不满意的段落让 AI 按你的修改意见重写；
4. 知识库依赖表先让 AI 按第 4 步的验证结果回填，勿凭想象写。

### 第 4 步：在 WorkBuddy 里验证知识库检索

对话中直接问："查一下知识库里 {你依赖声明里写的查询意图}"——AI 调 kb_search 返回的结果就是你技能运行时会拿到的。**搜不到就换意图表述或检查入库内容**，这一步通了，技能运行时才不会空转。

### 第 5 步：装载测试自己的技能

1. 把 SKILL.md 内容按技能管理系统指引入库上架（或临时粘贴给 WorkBuddy 对话作为系统指令快速预演）；
2. 用 3 种说法触发测试（"帮我编个可研"/"出一份 XX 项目可研报告"/"把这份材料做成可研"）；
3. 完整走一遍工作流：检查分派是否按映射表执行、产物是否过交付闸；
4. 问题定位：不触发→改 description；查不到库→改依赖声明或入库内容；产物不合格→收紧输出契约。

### 第 6 步：交叉自检并发布

与另一位责任人互查自检 8 项（第六节）→ 提交技能管理系统发布。此后迭代：修改→重测→重新提交，版本号进位。

## 六、开发推进（四阶段，7-8 天）

| 阶段 | 做什么 | 天数 | 关键并行 |
|------|--------|------|----------|
| 准备 | 定 2 名责任人（开发+知识库）、选 2 条业务线（高频/标准化/有素材）、领部门代码 | 第 1 天上午 | — |
| 建库 | 八目录框架 + P0 入库（模板×2 套/方法×2 份/案例×4-6 个） | 第 1-3 天 | A 线素材入库后即可启动 A 线技能开发 |
| 开发 | 智能体 SKILL.md×2（四件套）+ 功能技能×N（七段+依赖声明）；两人交叉自检 | 第 2-6 天 | 每套写完立即预演测试，不等全部写完 |
| 发布 | 3 次预演测试（触发/流程/产物）→ 逐项过自检清单 → 提交技能管理系统发布 | 第 6-8 天 | — |

**触发测试要点**：用 3 种不同说法表达任务（"帮我编个可研"/"出一份 XX 项目可研报告"/"把这份材料做成可研"），全部命中智能体才算过——不命中的话九成是 description 触发场景没覆盖。

**迭代**：任何修改重新提交，版本号进位（小修 +0.1，结构性 +1.0）；知识库每季度清理检查一次。

## 七、自检与发布（自检是质量的最后一道关）

**自检 8 项**（全部通过再发布，两人交叉互检效果最佳）：①命名合规（中文显示名+英文连字符+ID 无冲突）②description 三要素 ≤150 字 ③七段齐全（智能体含四件套）④至少启动/交付/失败三类闸口 ⑤知识库依赖表完整（dept+查询意图+未命中处理）⑥无密钥无绝对路径 ⑦输出契约含格式命名、终态为 Office 格式 ⑧3 种说法触发测试全命中。

自检通过后，将 2 套 SKILL.md（含自检清单与预演测试记录）提交技能管理系统发布。**开发过程中遇到任何问题（知识库操作、SKILL.md 写法、触发不命中等），随时联系Platform Platform Admin咨询**——宁可早问，不要带病发布。
