# 知识库权限配置指南

> 适用：SkillHarbor 门户知识库（MxsDoc 后端）· 2026-10-08
> 原则：**SkillHarbor 是唯一账号源**（密码只此一套），MxsDoc 侧为派生密码员工无感知；
> 库内容权限按"部门归属"分级，全部通过服务器脚本管理；**白名单的语义是"写权限名单"**（读取已全员开放）（勿直接在 MxsDoc 后台改账号密码，会被脚本校准覆盖）。

## 一、权限模型

| 角色 | 能看到什么 | 能做什么 |
|---|---|---|
| 本部门成员（白名单内） | 本部门库 + 被授权的跨部门库 | **本部门库**：上传/新建/改名/移动/删除；**跨部门库**：浏览/预览/下载（界面自动隐藏写按钮） |
| 白名单外员工 | **全部 14 库（只读）** | 浏览/预览/下载/搜索（2026-10-08 起：读取全员开放，走 kb-svc 共享通道不占 MxsDoc 账号；操作审计在 SkillHarbor 侧 kb-audit.jsonl） |
| kb-svc 服务账号 | 全部 14 库 | 只读+下载（供 AI 技能检索，不给写权限） |
| admin | 全部 | 平台管理（仅管理员掌握） |

账号上限：开源版 **50 用户**（当前 17，含 admin/kb-svc 两个系统账号）。接近上限时脚本会告警。

## 二、日常操作（都在服务器 127.0.0.1 上执行）

### 1. 开通 / 调整人员（改白名单后重跑同步）

```bash
ssh 127.0.0.1                # 端口 8422
vi  ~/data/mxsdoc/kb_whitelist.txt   # 一行一个用户名（SkillHarbor 拼音用户名），# 开头为注释
python3 ~/data/mxsdoc/sync_kb_users.py          # 增量同步：建号+按部门授权（幂等可重跑）
```

同步规则（自动执行，无需干预）：
- 新用户：建 MxsDoc 账号（密码=SkillHarbor 派生值），按其 SkillHarbor 档案部门授权**本部门库（可写）**；
- 已有用户：密码校准为当前 SkillHarbor 派生值（员工在门户改密后重跑本脚本即同步，正常情况自动自愈无需手跑）；
- 部门调动：改 SkillHarbor 侧部门档案 → 重跑同步即获得新部门库写权限（旧库权限不自动收回，用下面第 3 条手动收）。

### 2. 全量对齐 / 权限重刷

```bash
python3 ~/data/mxsdoc/sync_kb_users.py --fix-perms   # 按当前白名单+部门归属重刷全部授权（改权限规则后用）
python3 ~/data/mxsdoc/sync_kb_users.py --prune       # 删除白名单之外的普通账号（离职清理，慎用）
python3 ~/data/mxsdoc/sync_kb_users.py --all         # 全量 SkillHarbor 用户模式（受 50 上限保护，一般不用）
```

### 3. 给某人单独开跨部门库权限（如借调/项目组）

```bash
python3 - <<'EOF'
import json, urllib.parse, base64, http.cookiejar
jar = http.cookiejar.CookieJar()
op = urllib.request.build_opener(urllib.request.HTTPCookieProcessor(jar))
def post(p, d): return json.loads(op.open("http://127.0.0.1:8110/DocSystem" + p, urllib.parse.urlencode(d).encode()).read())
pw = open("/var/lib/mxsdoc/secrets/admin.password").read().strip().split(":", 1)[1]
post("/User/login.do", {"userName": "admin", "pwd": base64.b64encode(pw.encode()).decode()})
uname, vid = "yangxi", 11          # 用户名 + 目标库 id（规划所=11，getReposList 可查全部）
uid = next(x["id"] for x in post("/Manage/getUserList.do", {"page":1,"searchWord":uname})["data"] if x["name"] == uname)
# 只读授权必须双写（缺一会出现"看得见库读不了目录"）：
print(post("/Repos/configReposAuth.do", {"userId": uid, "reposId": vid, "access": 1})["status"])
print(post("/Repos/configDocAuth.do", {"userId": uid, "groupId": "", "reposId": vid, "docId": 0, "path": "",
    "name": "", "isAdmin": 0, "access": 1, "editEn": 0, "addEn": 0, "deleteEn": 0,
    "downloadEn": 1, "uploadSize": "", "heritable": 1})["status"])
# 收回权限：configReposAuth 传 access=0
EOF
```

## 三、常见问题

- **员工说"点知识库提示未开通"**：不在白名单 → 第一节第 1 条加名重跑；
- **员工改了门户密码后知识库进不去**：自动自愈（下次进入时重置派生密码）；若仍异常，重跑 `sync_kb_users.py`；
- **跨部门库需要写权限**（少数协作场景）：用第 3 条模板，把 `addEn/editEn/deleteEn` 改为 1；
- **MxsDoc 管理后台（8110 直登 admin）**：仅用于应急查看；账号/密码/授权以脚本为准，后台改动会被同步覆盖；
- **忘记 admin 密码**：`cat ~/data/mxsdoc/secrets/admin.password`（600 权限，仅 dt 用户）。
