# 智能体打包与上传说明（2.1.0）

本说明对应本次待发布版本。智能体是一个主编排技能，加上它调用的包内组件或平台已有技能；平台按结构识别，不依赖名称是否以 `-agent` 结尾。

## 新智能体推荐这样交付

把主入口、子技能、脚本、模板一起放入一个目录，在目录根部增加 `agent.yaml`，然后压缩整个目录。不要只选中主 SKILL.md 打包。

```text
example-business-agent/
  agent.yaml
  SKILL.md
  internal-skills/
    calculator.md
  scripts/
    render.py
  assets/
    template.docx
```

可从上传窗口下载[清单示例](../public/agent-template.yaml)。按真实文件修改 `id`、`entry`、`components` 和 `steps`：

- `id` 是资源的固定身份。更新已有智能体时沿用原 slug，不因中文显示名称变化而修改。
- `version` 是本次整体包版本。高级维护尊重明确填写的版本，冲突时需修正；智能发布在确认更新对象后由平台分配新发布版本，原始上传包保留。
- `entry` 是主编排文件相对清单的位置，例如 `SKILL.md` 或 `main/SKILL.md`。
- `components` 列出包内技能或脚本，路径相对清单；`steps.targets` 使用 `component:组件ID` 引用。
- `dependencies` 列出平台已经注册的外部技能，使用准确的 slug；步骤使用 `dependency:依赖ID` 引用。

包内技能随父智能体一起发布、更新和回滚，无需分别上传。它们不会自动出现在全局 AI 技能列表；需要跨智能体复用的技能，可以单独上架，再由各智能体声明为外部依赖。脚本详情支持查看源码，不会因为点开而执行。

## 上传时检查什么

点击“发布资源”并选择完整项目包。平台会自动整理类型、名称、用途和包内功能，正常情况下确认一页业务信息即可提交，不要求开发者填写入口路径、slug、版本或 YAML。

规则能够确认的关系直接整理；需要理解调用语义时，服务器通过网站现有 AI 网关，使用上传者已有的模型令牌辅助识别。模型只看到受控的说明片段和真实候选，建议仍须通过文件、资源和原文证据检查。没有本人模型令牌、服务超时或证据不足时，会保留规则结果与业务问题，不会伪称识别成功。

有多个可能入口或功能时，一次只显示一个业务问题，选择用途后继续。缺少必要功能时会保留草稿并提供“复制修复说明给开发助手”；补齐后重新上传完整包。平台不会把缺失功能自动改为可选或待建设来通过审核。

发现本人已有同名或同标识资源时，需要明确选择更新对象或发布为新资源。普通新项目在确认页显示本次新建，点击提交即确认；不会按相似名字自动更新。更新会继承原有标签、适用部门和展示设置。重新分析后旧确认过期，其他标签页需要同步最新结果并再次确认。

上传、识别中、问答、结果、错误、记录和高级维护共享固定尺寸窗口；长内容只在内部滚动。切换或刷新时按当前草稿 ID 恢复，原上传包与发布用派生清单分别保存。

## 高级结构维护

“高级发布 / 结构维护”保留给需要手工维护的情况。管理员直接上传仍经过严格预检。旧包或不规范包也可以在这里逐项完成修正：


1. 原文件安全检查通过后，即使主入口不明确，也会保留草稿。展开“修正智能体结构”，从实际文件列表中选择主入口。
2. 生成清单草案，核对固定 ID、版本和包内组件路径。多个组件名称相同时按路径选择；外部依赖可通过“改用包内组件”替换全部步骤引用。
3. 平台依赖选择准确的已注册标识；待建设依赖填写将来使用的固定标识，不要求它已经上线。
4. 点击“预览校验”。通过后可下载 `agent.yaml`，或点击“应用并重新检查”保存到本次上传包。修改任一字段后需要重新预览，旧预览不能继续应用。
5. 已有清单字段损坏时，页面提供明确的“重新生成清单草案”。重新生成后须核对原手工关系；平台不自动覆盖原清单。

应用只替换包根目录中的清单，保留主文件、其他子技能、脚本、模板和二进制附件。压缩包安全检查失败时不会创建可修正草稿。

| 提示 | 处理方式 |
|---|---|
| 缺少必需的外部技能 | 先发布该技能，或改为确实存在的准确 slug |
| 外部技能已停用 | 确认是否应启用或更换依赖 |
| 名称对应多个资源 | 用固定 slug 消除歧义 |
| 功能尚待建设 | 在清单中明确标记 `status: planned`；页面会显示待建设，不提供假链接 |
| 多个入口无法确定主包 | 在结构修正区选择入口并应用清单，或在最外层手工添加清单 |
| 主入口外还有兄弟文件 | 把清单放在能包含所有文件的共同目录，避免丢失 scripts/assets |

新清单中缺失、停用或不明确的必需依赖会阻止发布；可选依赖和明确标记的待建设项会提示警告。请按真实业务情况声明，不能为绕过校验而把必需项改成可选。

Windows 常见 GBK 中文目录 ZIP 可兼容；不能识别的编码会要求重新打包。统一推荐 UTF-8 ZIP。包文件上限 150 MiB，展开总量上限 250 MiB；不支持加密 ZIP、符号链接、越出包根的路径或大小写冲突文件。

## 已有包如何处理

已有 SKILL.md 和历史版本继续可用，不要求全部重新上传。`type: agent` 优先；未声明类型时，平台只对明确的任务映射、子技能调用链等编排结构推断智能体，不依据依赖当前是否启用改变资源类型。

“同上”“见第四节”、自然语言技能名与实际 slug 不一致等信息，可能仍显示待修正。平台保留这些提示，不会猜测并跳到相似的技能。后续更新该包时补上清单即可逐步消除歧义。

查看详情时，可进入包内子技能或外部技能，再通过面包屑返回主智能体。包内详情固定在父包版本，避免主入口和子技能来自不同版本。MCP 调用主技能后也会返回组件信息，可使用 `load_skill_component(slug, component_id, version)` 读取对应组件。

## 跟踪发布与管理依赖

工作台的“我的资源”集中显示本人草稿、待审核、已上线及失败记录，可按类型、状态和关键词筛选。继续编辑会恢复指定草稿，不会误打开另一份。新版本驳回后保留原包，允许修正后重提；历史上已经清理的文件仍需重新上传，原表单信息会带回。

更新已有资源必须选择本人有权更新的对象，并沿用它的固定标识。新建包即使使用不同展示名称，也不能占用现有资源标识。已确认绑定的草稿不能在提交时偷偷取消或切换目标。

管理员可在“技能中心 → 依赖问题”查看缺失、停用、匹配不明确和待建设项。停用资源前会显示当前版本中引用它的智能体或技能，区分准确引用和歧义候选；检查失败或扫描不完整时不能确认停用。该检查只读，不会批量改清单或级联停用其他资源。
