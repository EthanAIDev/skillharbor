# 智能上传真实 HTTP 回归

`scripts/test-smart-upload-integration.cjs` 启动真实门户和技能网关，验证上传、分析、问答、自动规范化、提交审核与审批发布。只有模型补全使用本地 HTTP 模拟服务；门户模型客户端、提案校验和网关分析均运行真实代码。

## 运行

需要 Node.js 22 或更新版本、带依赖的网关 Python 环境，以及包含 `/api/skills/analyze` 的网关代码。在门户仓库执行：

```powershell
node scripts/test-smart-upload-integration.cjs --gateway C:\path\to\skill-gateway --python C:\path\to\venv\Scripts\python.exe
```

也可设置 `GATEWAY_REPO` 和 `GATEWAY_PYTHON`。脚本通常约需 15 秒，成功输出 `23` 个测试通过（22 个场景及外层测试）；任何断言失败均以非零码退出。无需预先启动服务或提供真实凭据。

## 隔离与原文件检查

- 门户、网关各自使用系统临时目录下的新数据目录和随机 `127.0.0.1` 端口。模型模拟服务也仅监听随机本机端口。
- 仅创建管理员、上传人、另一上传人三个合成账号。子进程不继承开发机上游配置或凭据；知识库、One API、IP 同步等地址统一指向 `127.0.0.1:1`，关闭告警轮询，Docker 使用 mock。
- 模型客户端仅使用本次合成的 `PACKAGE_AI_KEY` 和 `PACKAGE_AI_BASE`；模拟服务验证 Bearer 和上下文合同，不访问真实模型，也不消耗配额。
- 每次 parse 都核对 `upload-originals/<id>.bin` 与原上传字节完全相等。每次发布再次核对原包；技能发布还核对记录中的 SHA-256，确认原归档和分析源快照没有进入发布版本。网页工具则通过 HTTP 读取发布页，检查与本次上传 HTML 完全一致。
- 包内兄弟入口、文本及二进制文件通过 SHA-256 检查，确保规范化只改变清单，不删减原项目。
- 正常或失败退出均停止本脚本启动的服务，校验临时目录范围后清理数据。不会连接既有 18800、生产网关或生产快照。

## 覆盖场景

1. 普通技能自动写入合法规范清单，资源类型保持 `skill`，无需高级编辑即可提交、审批并发布；分析不写注册表。
2. 真实调用包内子技能的智能体返回业务功能摘要及步骤，任意目录下的组件、模板和二进制资产均保留，发布后组件正文可读。
3. 多入口先返回未选择的问题，不生成可提交结果；使用响应中的 opaque option ID 选择入口后 ready，重复分析仍保留所选入口与全部兄弟文件。
4. 必需功能缺失时 blocked，提供修复说明，禁止提交，注册表和原上传保持不变。
5. 模型 HTTP 503 时保留真实业务问题和规则引擎标记；用户选择后可完成发布，不会重复请求模型。
6. 模型根据真实上下文构造 `resolutions` 和逐行 evidence，经 Node 客户端及真实网关验证后变为 ready，返回 AI 证据并发布。
7. 模型伪造原文证据时，Node 客户端回退到问题；将同类伪造 proposal 直接交给真实网关也被 `invalid_proposal` 阻止。不能提交，注册表不变。
8. 本人已有的精确身份返回 `publication-identity` 的 new/update 选项；主动选择 update 后才持久化绑定，发布新版本并保留旧版本内容。
9. 已确认更新不能仅用空 `updateOf` 取消；必须携带 `newResource: true` 重新规范化，生成新身份，原目标元数据和文件不变。
10. 在本人精确身份问题中主动选择 new，发布独立新项目，不改动原资源。
11. 本人多个同名项目返回准确的 `update:<slug>` 选项，不默认选首项；选择第二项只更新该资源。
12. 更新意图仍需要回答入口问题时，仅保存待确认意图，不提前修改真实 `rec.updateOf`；后续只提交入口答案也能继承意图并完成更新。
13. 碰到他人已有身份时生成不同的新 ID，以新建方式发布，原所有者的元数据、版本及文件 SHA-256 不变。
14. 另一用户及管理员不能操作上传人的 analyze/draft；缺少或过期 revision 返回 409，待审记录不能再次分析，拒绝操作不改变持久化状态。
15. 用模型响应屏障稳定制造分析中的并发窗口；重复 analyze、draft 保存、submit 均返回 409，释放后只推进一次 revision。
16. 草稿业务名称、说明和更新说明可保存；驳回保留分析记录、原包及文件，重新分析、修改说明和提交后可以发布。
17. 高级 prepare 修改入口、kind、版本和手工步骤后，旧分析源失效；回到智能分析使用手工清单，发布结果保留这些明确修改。
18. 用户确认 revision 1 后，重新分析推进至 revision 2；提交旧 revision、漏传 revision 或字符串 revision 均返回 409，草稿状态和文件不变，只有已确认的当前 revision 能提交。非智能草稿显式提供 revision 时同样校验，正确的 revision 0 可正常发布。
19. HTML 网页 ZIP 附带有 name/description 的普通 README 时仍识别为工具；发布后再上传同名工具会出现 new/update 问题，两种回答均恢复原始合法检查报告，不会被问题阶段的失败报告锁住。更新保持工具 ID 和 URL，新建产生独立工具，再次分析也保留对应意图，发布的 HTML 内容可通过 HTTP 验证。
20. 身份题选择 update 完成后清除待答题及旧 publication choice；随后明确改为新建并重试，仍保留新身份。再手动选择另一更新对象后重试，也保持最新目标，不会重放先前答案或改动原对象。
21. ZIP 只有合法 name/description 的 `main.md` 与 `parts/calculator.md`，没有 `SKILL.md`、HTML 或后端入口时，也能进入技能分析并提供候选；选主入口后发布，原文件 SHA-256 保持一致。
22. `main/orchestrator.md` 显式声明 `type: agent` 时，包根 HTML 模板不会将其误判成网页工具；能正确分析主入口及子技能并发布，HTML 模板和其他原文件保留。

## 接口边界

每次 `POST /api/uploads/:id/analyze` 都传当前 `revision`，首次为 `0`。成功返回 `{ok,id,analysis,report,revision}`，下一次请求使用新 revision；question 和 blocked 也会递增。问题答案使用返回的题目 ID 和选项 ID，不能猜测文件路径。门户发布身份问题不应作为网关包内问题透传。

智能草稿提交 `POST /api/uploads/submit` 时必须携带用户实际确认结果的整数 `revision`。测试客户端只记录已经收到的分析 revision，并在发布时显式使用该结果的 revision，不在提交前查询服务器来悄悄升级确认版本。无智能分析的旧客户端仍可省略该字段；原兼容回归脚本保持不变。

ready 自动规范化后仍能重放此前问答；高级清单应用必须更新分析源。原始上传和分析源快照分别保存于发布包外，不能用规范化清单覆盖原始归档。

测试报告针对本地后端集成，不替代浏览器布局、真实模型质量或线上部署验收。旧上传、安全 ZIP、大文件、GBK 与管理员上传限额继续由 `scripts/test-skill-integration.cjs` 覆盖；该脚本不在本轮修改范围内。
