## 一、这是什么

一套按公司《智能体技能开发指南》v2.0 开发的"技能开发支持"技能，共 5 份 SKILL.md，按开发对象分两条线，同时是Platform交付的智能体样板件（满足智能体结构四特征）：

```
智能体开发智能体（zlb-skilldev-agent，智能体线主编排）
技能开发智能体（zlb-funcdev-agent，功能技能线主编排）
├─ 技能开发-规范自检（tool-skill-lint）    静态八项检查：命名/frontmatter/description/
│                                          三要素/七段/四件套/闸口/红线
├─ 技能开发-知识库验证（tool-kb-verify）   依赖表逐行 kb_search 实测 + P0 就绪度探测
├─ 技能开发-触发推演（tool-trigger-sim）   description 触发覆盖推演 + 真机实测话术
└─ （分派）【skill开发】技能               三层引导生成 SKILL.md 草稿
```

两条线按对象类型互为转介：说"智能体 / 新建 Agent"→ 智能体开发智能体；说"功能技能 / 工具技能"→ 技能开发智能体；说"有哪些现成技能能拼"→ 智能体开发智能体（组装推荐单派）；三项检查工具共用。

配套：《SELF-CHECK-REPORT.md》递归自检报告（v1.0 八项全过 + v1.1 复验①-⑦通过，含真机验证记录与改造清单）。

## 八、网关依赖（2026-10-26 起要求 ≥ `p12-20261026`）

本套件的部门归属校验（D2）与知识库依赖实测（`tool-kb-verify`）都经网关 `kb_search` / `kb_list` / `kb_get` / `kb_upload` 取数，而依赖表按规范写的是**部门代码**（`dept=zlb`）。网关侧曾有两个缺陷，导致按代码调用必然失败：

| # | 缺陷 | 表现 | 修复 |
|---|------|------|------|
| 1 | `vid_by_dept()` 直接拼 `f"{dept}知识库"` 当仓库名，无归一化 | 传 `zlb` 报"未找到部门「zlb」的知识库"；技能只能人工翻成中文名，或按失败闸降级到内嵌部门表并标"部门表待核" | 新增 `DEPT_CODE_TO_NAME`（14 部门）+ `dept_name()`：代码/中文名、大小写、`知识库` 后缀、全角空格均可；未知标识仍报错不串库 |
| 2 | `_get_json()` 形参 `path` 与门户 `/api/kb/list` 的查询参数同名 | `kb_list` 任何调用都 `TypeError: got multiple values for 'path'`——技能失败闸里"用 kb_list 看目录确认是否入库"这条降级路径从未可用 | 形参更名 `url_path` |

**实测（真实 MCP 通道，网关 p12）**：`zlb` / `ZLB` / `zlb知识库` / 带空格 `zlb` 全部解析为Platform库（vid=2），命中结果与 `dept=Platform` 完全一致；`ghs` 与「规划所」同指 vid=11；未知 `zlbx` 仍报错。`kb_list`、`kb_get` 均正常。

**部署与回滚**：生产机（`127.0.0.1`）只挂 compose + .env + data 卷、**不放源码**，不能就地 `--build`。镜像标签即版本（`p10j-20261020` → `p11` → `p12-20261026`），回滚只需把 `docker-compose.yml` 的 `image` 改回旧标签再 `docker compose up -d`，历史镜像全部保留。
