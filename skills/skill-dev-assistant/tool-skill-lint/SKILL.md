## 1. 功能描述

对一份 SKILL.md 做**静态规范检查**（不调用外部工具、不做真机测试）：命名与标识、frontmatter、description 三要素、七段结构、智能体四件套、闸口、知识库依赖表、红线扫描，覆盖公司自检 8 项中的①②③④⑤⑥⑦，并按被检对象的 type（agent / functional）自动切换两套标准。支持**单项快检**：只查用户指定的某几项，出对话结论、不落文件。

**边界**：

- 内：①八项静态检查与整改建议；②给出不合格片段的改写示例；③引用规范原文说明判定依据；④单项快检（指定项）。
- 外（不做）：①知识库依赖的在线实测（转 tool-kb-verify）；②description 触发覆盖推演与语义撞触发检测（转 tool-trigger-sim）；③整篇代写 SKILL.md；④业务内容正确性判定；⑤以快检结论替代完整检查或作为发布依据。

## 2. 输入契约

**必需**：SKILL.md 全文（含 frontmatter，粘贴或文件内容）。

**可选**：部门代码（未提供时从 frontmatter 的 owner_dept 读取）；特殊说明（如"这是我们改版后的 v2"）；**快检指定项**（如"只查命名"时说"快检 ①"，则仅输出①项结论）。

## 3. 输出契约

| 交付物 | 格式 | 命名 | 质量标准 |
|--------|------|------|----------|
| 规范自检报告 | Markdown（正式汇报版可导出 DOCX，导出路径交付时给出） | `lint-{技能name}-{YYYYMMDD}.md` | 八项逐项：结论（通过/警告/不通过）+ 证据（引用被检原文行）+ 整改建议 + 改写示例；每项标注判定来源（AI 判定 / 库内规范原文 / 内嵌规则） |
| 整改片段集 | Markdown（报告内嵌） | — | 不合格项的"改前 → 改后"对照片段，可直接粘贴替换 |
| 快检结论（仅快检模式） | 对话输出，**不落文件、不入档** | — | 仅含指定项结论 + 整改片段；首行强制标注"单项快检，未经完整八项检查，不可作为发布依据" |

结论分级：**通过**（满足要求）/ **警告**（建议级，不阻断发布，如两段式命名未用）/ **不通过**（违反强制规则或红线）。

## 4. 工作流

1. **前置**：读取 frontmatter 判定 type（agent=智能体 / functional=功能技能）→ 选择对应检查清单（agent 清单 = 八项全量 + 四件套 + 智能体结构四特征；functional 清单 = 八项中适用项，不查四件套）。
2. **查库核版**：调 kb_search(dept="public", 目录"Platform/02-方法论库", 意图"智能体技能开发指南 SKILL.md 编写标准") 确认指南版本。公司级规范统一在公司公开库（全员只读），**不得引用Platform等私有库**——部门库跨部门不可见，引用即报无权访问。本技能内嵌规则对应指南 v2.0（2026-10-08），若库内版本更高，以库内为准并提示；未命中时按内嵌清单执行并标注"规范库待核"。部门代码校验（A3/A5）一律用下方内嵌 14 部门表，**不查库**——判定须有确定性。
3. **逐项检查**（下列清单），每项记录：结论 + 证据行 + 整改建议。
4. **汇总**：按①-⑧顺序输出报告；存在"不通过"时给出整改优先级排序（红线类最先）。

**项间边界表（先读此表，再逐项检查；重叠缺陷只在主项出结论，附项写"见第 X 项"，不重复计入不通过数）**：

| 项 | 唯一判定职责 | 不判（转出） |
|----|--------------|--------------|
| ② description 三要素 | 字数是否 ≤150、三要素是否齐备 | 触发能否命中 → 转 ⑧ 与 tool-trigger-sim |
| ⑤ 知识库依赖表 | 五列是否齐、dept 是否本部门、未命中处理是否三选一 | 依赖能否真查到 → 转 tool-kb-verify |
| ⑧ 触发测试 | 静态段仅登记"是否已转 trigger-sim"，不出覆盖结论 | 覆盖度与命中结论 → 转 tool-trigger-sim |
| ① A6 防撞 | 标识层冲突（name / display_name 与现有清单） | 语义层冲突（会不会抢别人触发）→ 转 tool-trigger-sim 冲突模式 |
| ⑦ 输出契约 | 格式、命名、质量标准和是否声明汇报版导出路径 | 产物内容质量 → 不判 |

**内嵌检查清单**（v2.0 规则 + 2026-10-10 v1.1 补充：A5 多部门多值 / A6 防撞 / ③适用对象警示；2026-10-26 v1.3 补充：③映射表只计分派行 / 部门表改引知识库 / ⑦豁免口收紧，规则与库内指南不一致时以库内为准）：

**① 命名与标识**

| # | 规则 | 级别 |
|---|------|------|
| A1 | 显示名中文、≤20 字；agent 型必须为"{业务名}智能体"格式；functional 型禁用"智能体/专家/调度"字样 | 强制 |
| A2 | 分隔符为英文连字符 `-`，不用全角破折号；工具型建议两段式 `{能力域}-{具体功能}` | A2 前半强制 / 后半建议（警告级） |
| A3 | 系统 ID 全小写英文/拼音，无中文/空格/下划线；agent 型 `{部门代码}-{业务代码}-agent`；工具型 `tool-` 前缀；部门代码须在部门代码表内（校验源见下） | 强制 |
| A4 | frontmatter 七字段齐全：name / display_name / type / subtype / version / owner_dept / description；name 与 ID 一致；type∈{agent,functional}；subtype∈{business,tool} | 强制 |
| A5 | owner_dept 为合法部门代码；多部门联合开发支持多值（`+` 分隔，如 zlb+ghs，每段均须在部门代码表内，首个为主责部门） | 强制 |
| A6 | 防撞：name（系统 ID）与 display_name 不得与已上架技能冲突。本技能为静态检查不联网实测——用户提供技能清单（如 list_skills 结果）或已知同名技能时判"不通过"并给出冲突对象；无法核验时报告须标注"防撞未核验，上架前调 list_skills 复核" | 冲突可证时强制 / 无清单时标注 |

**A1 判定须知（2026-10-26 因实战误判补充）**：判命名合规**必须先读被检文件 frontmatter 的 `type` / `subtype` 实际值**，严禁由技能的业务语义或 display_name 字面反推类型。agent 型查尾缀 `{业务名}智能体`、functional 型查禁词"智能体/专家/调度"，两者判据互斥——同一份文件用错类型分支会得到完全相反的结论。同类实例：本套件两条主编排都管"开发技能"，但 `zlb-funcdev-agent` 名字含"功能技能"却是 `type: agent / subtype: business`，若按名字推断为 functional 型会误判其合规显示名为违规。**此项须在报告的 A1 证据行中显式写出被检 type/subtype**，供复核。

**部门代码校验源**：以下表为准（内嵌判定，不查库）。公司公开库《部门代码与归属对照表》为其同步副本，供人工查阅比对，**不作为运行时依赖**。全公司有效部门 **14 个**（含董事会与投资部；监事会不设，无代码）。早期文档写作"15 部门代码表"系误计，本表为准。

**部门代码表（内嵌，共 14 个；与公司公开库《部门代码与归属对照表》同源）**：Platform zlb、咨询所 zxs、新能源事业部 xnsyb、市场部 scb、设计院 sjy、总经办 zjban、研究院 yjy、规划所 ghs、财务部 cwb、环碳院 hty、新能源所 xnys、投资部 tzb、政技部 zjbu、董事会 dsh（监事会不设）。

> 易错对：新能源事业部 `xnsyb` 与新能源所 `xnys` 为两个不同部门，勿按拼音印象互串。

**A4 附注（2026-10-26 因路由隔离新增）**：frontmatter 允许出现可选第八字段 `routable`（true / false，缺省 true）。它**不属于七字段强制范围**，出现即视为合法，不得判为"多余字段"。语义：`routable: false` = 内部技能，不进 search_skills 候选集与 list_skills 清单，只能被父智能体按 slug 调取；`routable: true` = 可被提示词直接触发。判 A4 时只核七字段是否齐全，**不因 routable 的有无或取值升降级**；若工具型技能明显是被智能体分派的内部能力、却未声明 `routable: false`，出**警告**级提示"建议声明 routable: false，否则提示词可能直接命中该工具"。

**② description 三要素**：≤150 字；含①干什么（一句职责）②何时触发（任务表述）③输入什么输出什么；出现"强大的/智能的/全能"等空泛词而无实质信息 → 警告。

**③ 结构完整性**：七段齐全按序（功能描述/输入契约/输出契约/工作流/闸口/知识库依赖/约束红线）；agent 型另查四件套：

- SOP 阶段表（阶段/工作内容/依赖技能/产物）；
- 任务→功能技能映射表：**分派行 ≥2 行且分派技能不重复**（对应结构特征三"调度多个技能，而非单个技能独立运行"）。仅计"分派技能"列为其他技能的行使；写作"本智能体自查""本智能体调 list_skills""本智能体查库直答"等自执行行单列，**不计入分派行数**；自执行行 ≥3 行时出**警告**"自执行占比过高，考虑下沉为功能技能"；
- 分派规则为可执行判定条件（如"消息含 X 且提供了 Y → 分支 1"），出现"灵活判断/酌情/视情况"→ 不通过；
- 产物收口段存在且含汇总核对动作（只转发不收口 → 不通过）。

**适用对象警示（执行时逐条核对自己引用的规则是否适用被检对象）**：四件套（SOP 阶段表/映射表/分派规则/产物收口）与结构特征三"调度多个技能"均为 **agent 型专属标准**；functional 型不查四件套——功能技能只做一件事，不得以"未调度多个技能"或"缺四件套"判 functional 不合格，误引即报告作废重出。

**④ 闸口**：至少声明启动/交付/失败三类；闸口名须用五类标准名（启动闸/数据闸/阶段闸/交付闸/失败闸），自造概念 → 警告。

**⑤ 知识库依赖表**：表五列（工作流步骤/dept/目录/查询意图/未命中处理）；dept 写死本部门代码或 `public`（公司公开库；写"动态/任意/全部"→ 不通过）；目录在八大目录内（01-模板库/02-方法论库/03-案例库/04-政策法规库/05-数据资料库/06-标准规范库/07-术语口径库/99-归档区）；查询意图为自然语言；未命中处理为三选一（换词重试/降级标注估算/停下询问），出现"静默跳过/编造来源"→ 不通过。工具型技能确实不用库 → 第六段写"无知识库依赖"及原因，视同通过。

**⑥ 红线扫描**：无密钥口令（password/secret/token/apikey 等赋值样式）；无个人电脑绝对路径（`C:\`、`D:\`、`/Users/`、`/home/` 开头的路径引用）；引用数据须标注来源要求；一个技能只做一件事（功能描述出现两个以上不相关职责 → 拆分建议）。

**⑦ 输出契约**：正式产物为 Office 格式（DOCX/XLSX/PPTX）；含交付物命名规则；含质量标准。纯工具型输出 md 报告的（检查/分析类产物），须在第 3 节输出契约显式声明"正式汇报版可导出 DOCX"及导出方式——已声明视同通过；**未声明判警告级**（不阻断发布），报告提示"需 DOCX 汇报版可另行导出"。检查器自身产物同样适用本条，不得以"检查类产物"自我豁免。

**⑧ 触发测试**：静态阶段仅核 description 是否写明触发场景（与②联动）；真机 3 种说法测试转 tool-trigger-sim。

**智能体结构四特征对照**（**仅 agent 型**输出附表，functional 型不出此表——特征三只约束智能体）：①以业务逻辑为核心 ②配置专属知识库（第 6 段依赖表非空且 dept=本部门）③调度并协同多个技能（**分派行 ≥2 行且分派技能不重复**，自执行行不计）④可交付他人使用（输入/输出契约完整）。缺任一 → 顶部标红"不满足智能体结构特征"。

## 5. 闸口

| 闸口 | 时机 | 动作 |
|------|------|------|
| 启动闸 | 检查前 | 确认拿到完整 SKILL.md（含 frontmatter）；缺 frontmatter 先提示补齐再检。**快检模式**：用户明确指定单项（如"快检 ①""只查命名"）时，仅确认该项所需输入即可启动，不要求全文完整性声明 |
| 数据闸 | 引用规范条文/部门代码作判定依据前 | 规范条文以公开库指南原文为准并注明出处（未命中时以内嵌规则回答并标注"规范库待核"）；部门代码一律以内嵌 14 部门表为准，不查库 |
| 阶段闸 | （本技能单轮完成，无中间产物确认环节） | — |
| 交付闸 | 报告输出前 | 逐项核对八项均有结论、每项有证据行与判定来源；"不通过"项均有整改建议与改写示例；快检输出须带"不可作为发布依据"首行标注且未落文件 |
| 失败闸 | frontmatter 残缺无法判定 type / 内文非 SKILL.md / 快检指定项超出①-⑧范围 | 停止检查，说明原因请用户补齐或改指定项，禁止猜 type 强行检查 |

## 7. 约束红线

1. 判定只引用被检原文与规范原文，逐项给证据，不凭印象；
2. 警告级与不通过级严格分级，不得把建议级问题报成阻断级（反之亦然）；
3. 不代写整篇 SKILL.md，只给片段级改写示例；
4. 业务内容对错不判定，只检规范性；
5. 无密钥、无绝对路径；本技能不修改任何知识库内容；
6. 快检结论不得落文件、不得写入任何检查档案、不得作为发布依据，输出须带"未经完整八项检查"标注；
7. 重叠缺陷按"项间边界表"只在主项计一次，不得重复计入不通过数；四件套与结构特征三仅适用于 agent 型，误引即报告作废重出。
