## 1. 功能描述

把**一次会议的纪要原文**转化为**结构化待办清单**：逐段扫描、识别行动信号、剔除伪待办、补全字段、标注缺口，最终交付一份每条都可回溯到原文的 XLSX 待办表（含待确认事项分表）。

核心判据是**可核查**：任一条待办都能指向纪要中的某句话，任一个责任人和日期都有原文依据或明确标为「待确认」。宁可留空并标注，不可推测补全——这是本技能与「让模型读一遍纪要随便列几条」的根本区别。

**边界**：

- 内：①纪要正文的段落级扫描与行动项识别；②伪待办过滤与同事项去重；③责任人/协作方/截止日期/优先级/完成标志的字段补全与缺口标注；④相对时间按会议日期绝对化；⑤XLSX 待办表与对话内速览表交付；⑥字段完整性自检。
- 外（不做）：①撰写、润色、改写会议纪要本身；②评价会议组织质量、决议合理性、责任分配是否公平；③把待办推送到企业微信待办、邮件或日历（不串联其他技能，交付文件后由用户自行分发）；④从录音、视频中做语音转写（输入须为已转写文本；提供音频时请用户先转写）；⑤跨多次会议的任务跟踪与状态更新；⑥补充纪要中不存在的背景信息、进度数据或验收标准。

## 2. 输入契约

**必需输入**：

| 输入 | 说明 |
|------|------|
| 会议纪要原文 | 全文粘贴，或本机 docx/txt/md 文件路径。单次处理一份会议；多份纪要需分次调用。图片截图或扫描件须先转文字，本技能不做 OCR |
| 会议日期 | 相对时间（下周、月底、节后、本周内）换算的**唯一基准**。条件必需：纪要中全部为绝对日期时可缺省；存在任一相对时间表述且原文未写明会议日期时，必须先问明日期的年月，不得以当天日期代入 |

**可选输入**：参会人员名单（用于同名消歧，如两位「张工」）；部门简称与实际名称对照（用户自备，本技能不查库映射）；优先级规则覆盖（用户另有 P0/P1/P2 判据时以用户为准）；输出目录（默认当前工作目录）；只要对话速览不要 XLSX 的明确指示。

**输入预检**（任一项不满足即触发启动闸问询）：纪要是否为一次性完整提供（中途截断、标注「以下略」的需确认）；是否包含议题与结论段落（纯通知、纯工作汇报、纯寒暄聊天记录不适用）。

## 3. 输出契约

| 交付物 | 格式 | 命名 | 质量标准 |
|--------|------|------|----------|
| 待办清单表 | XLSX（两个工作表：`待办清单`、`待确认事项`） | `待办清单-{会议主题}-{YYYYMMDD}.xlsx`，日期取**会议日期**（会议日期不详时取生成日期并在交付说明中注明）；会议主题取纪要标题或首个议题名，先去除文件名非法字符（反斜杠、正斜杠、冒号、星号、问号、双引号、尖括号、竖线）再截断至 20 字 | 九列齐全（序号/待办事项/责任人/协作方/截止日期/优先级/完成标志/来源原文/状态）；每条均有来源原文摘录；责任人与截止日期无空单元格（填实值或填「待确认」）；截止日期全为 `YYYY-MM-DD` 绝对格式；优先级仅取 P0/P1/P2；状态列默认「未开始」 |
| 对话内速览表 | Markdown 表（**不落文件**） | — | 仅含序号/事项/责任人/截止/优先级五列；表后附「待确认 N 项」与自检说明两句以内 |
| 待确认事项清单 | XLSX 第二工作表 + 对话内要点 | 同上文件 | 每行给出：对应待办序号、缺失字段、原文表述、需向谁确认；无缺口时该表写一行「无」 |

**优先级判据（自上而下命中即定，不叠加）**：

| 序 | 条件 | 级别 |
|----|------|------|
| 1 | 原文标注紧急/尽快/特急，或涉及对外报送、对上汇报、合规与安全事项 | P0 |
| 2 | 有明确截止日期且距会议日期 ≤7 个自然日 | P0 |
| 3 | 有明确截止日期 | P1 |
| 4 | 无截止日期但有明确责任人 | P2 |
| 5 | 无截止日期且责任人待确认 | P2（同时进待确认表） |

如需在会上汇报，可基于同一份清单另导出 DOCX 版任务分派表（按责任人分组、A4 纵向、表格不跨页断行）。

## 4. 工作流

**步骤 1 接入与切块**：读取全文 → 提取会议主题、会议日期、参会人（如有）→ 按议题或发言人切分为若干内容块，逐块编号备用。会议日期须在正文中定位到明确日期或经启动闸问明。

**步骤 2 逐块扫描行动信号**（每块至少判定一次「有/无行动项」，不得整篇跳读）：

| 信号类型 | 原文特征 | 处理 |
|----------|----------|------|
| 明确指派 | 「由 XX 负责/牵头/承办/对接/跟进」 | 责任人取被指派方；协作方取同句并列主体 |
| 主动承诺 | 第一人称 + 动作 + 时间（「我这边下周三前出初稿」） | 责任人为发言人 |
| 决议落地 | 「确定/同意/通过 + 方案」 | 生成推进类待办，标注「由决议推断」，责任人不默认填主持人 |
| 时限型要求 | 「必须/需要 + 在 X 前 + 做 Y」 | 日期取 X；责任人按同句或上下文指定方 |
| 待跟进事项 | 「等 XX 反馈/待确认/再对接」 | 生成跟踪类待办，完成标志为「收到反馈」 |

**步骤 3 过滤与去重**（下列内容不生成待办）：

- 背景介绍、历史回顾、现状陈述、数据罗列；
- 观点表达与未形成结论的分歧（「有人认为……但也有人担心……」）；
- 已完成事项（「上次我们已交付」）——不列入，必要时在对应条目的备注中留痕；
- 无主体、无动作、无时间的泛泛表态（「要高度重视」「加强协同」）；
- 会议程序性内容（「下面进入第二项议题」「大家看下材料」）。

同一事项在多处出现时合并为一条，来源原文取最完整的一处，并在末尾注「原文提及 N 处」。

**步骤 4 字段补全**：事项描述用「动词 + 对象 + 交付物」写法，保留原文关键动词，不做同义替换导致语义漂移；责任人依次取 姓名 → 部门/角色 → 「待确认」（推断所得标「推断：XX」，并在待确认表提示复核）；相对时间按会议日期换算并回显换算依据。

**步骤 5 缺口标注**：责任人缺失、日期缺失或表述歧义（「尽快」「适当时候」「下周找个时间」）、完成标志不明，逐条写入待确认事项表，注明需向谁确认。

**步骤 6 生成交付物**：写 XLSX（表头加粗、首行冻结、列宽适配、截止日期列设为日期格式）→ 输出对话内速览表 → 说明文件落地路径。

**步骤 7 自检收口**：对照原文回扫一遍，确认每块已判定过；核对九列无空缺、日期已绝对化、无原文无据条目；「待确认 N 项」与第二表行数一致。自检不通过则补正后再交付，不得带缺口交付。

## 5. 闸口

| 闸口 | 时机 | 动作 |
|------|------|------|
| 启动闸 | 收到输入、开始扫描前 | 确认四项：①纪要完整可读（截断、图片、音频未转写 → 请用户补齐）②会议日期（缺失且有相对时间 → 必须问明，禁止用当天日期）；③无待办时是否仍要出空表（默认出一份标注「本次会议未形成明确行动项」的表）；④输出形态（默认 XLSX + 对话速览）。非纪要内容 → 走失败闸 |
| 数据闸 | 责任人、协作方、截止日期写入表格前 | 逐条核原文依据；推断值标「推断：XX」，无据填「待确认」；相对时间换算结果在对话中回显「原文表述 → 换算结果（基准：会议日期）」供用户核对，用户提出异议即改 |
| 阶段闸 | 候选待办 >15 条，或原文 >5000 字，或含 3 个以上议题 | 先输出候选清单（序号/事项/责任人/截止日期）请用户确认增删与合并，确认后再生成 XLSX。≤15 条且单议题时单轮直给，不增设往返 |
| 交付闸 | 文件写出前 | 九列齐全且无空单元格；每条有来源原文；日期全绝对化；待确认项已单列且计数一致；文件名符合命名规则；无原文无据条目。任一项不满足即补正，不得带缺口交付 |
| 失败闸 | 非纪要内容 / 全文无任何行动项 / 会议日期无法确定而相对时间占比超过 30% / 无法写出 XLSX | 停止并说明缺失项，请用户补充后重来；XLSX 写失败时降级为 CSV（UTF-8 BOM，Windows Excel 直接可读），并在交付说明首行标注「降级产物，非 Office 正式版」。**禁止为凑数虚构条目、虚构责任人或虚构日期** |

## 6. 知识库依赖

**无知识库依赖。** 原因：①输入即待办清单的唯一信息源，输出为其派生结构，不引用任何外部资料；②责任人与部门一律照原文摘录，不做部门代码映射，避免引入原文不存在的归属信息——用户如需统一部门名称，可在输入契约的「部门简称对照」中自带一份；③技能运行不联网检索，避免把外部信息混入会议事实。若后续需要跨会议任务台账或人员名录，另行立项，不在本技能内扩展。

## 7. 约束红线

1. **不臆造**：原文无据的待办事项、责任人、截止日期一律不填；缺失即标「待确认」，禁止以「合理推测」「行业惯例」补全。宁可少列一条，不可多编一条。
2. **可溯源**：每条待办必须有来源原文摘录（逐字，≤50 字，可用省略号但不得改词换词）；摘录与事项描述指向不一致的，以原文为准修正描述。
3. **时间基准唯一**：相对时间一律以**会议日期**为基准换算，严禁以系统当天日期代入；换算结果须回显依据，供用户核。
4. **讨论不等于决议**：仅在出现明确结论表述时生成决议类待办，且必须标注「由决议推断」；调研中未定的事项列为待跟进，不得升级为任务。
5. **不改写原意**：事项描述保留原文关键动词与限定条件（如「初稿」「征求意见稿」不得合并为「完成报告」）；来源原文为逐字摘录，不得润色。
6. **只做一件事**：不撰写或润色纪要、不评价会议质量与决议合理性、不派人、不推送任务、不串联其他技能；跨会议跟踪与录音转写不在本技能范围。
7. **隐私与数据安全**：纪要原文不写入任何知识库、不上传外部服务、不在对话中复述与待办无关的敏感内容（人事、薪酬、未公开商务条款）；输出文件仅落在用户指定目录或当前工作目录。
8. **无硬编码**：不出现密钥、口令、账号与个人电脑绝对路径；文件路径由用户指定或取当前工作目录。
